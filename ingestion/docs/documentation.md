### Ingestion processing docs

The pipeline consists of four Airflow DAGs running on Astro CLI in Docker, each scheduled daily at 7:00 AM. Three DAGs handle data ingestion: one pulls use-of-force incident data from the Montgomery County open data portal via the Socrata OData API, one pulls crime report data from the same portal via the Socrata JSON API, and one pulls police dispatch data also via the Socrata JSON API. All three follow the same extract-transform-load pattern — data is fetched with pagination, written to a temp file to avoid Airflow's XCom size limits, cleaned in a second task, then loaded into Neon PostgreSQL in a third task.

The cleaning step is consistent across all three DAGs. Column names are normalized to lowercase with underscores. Duplicate rows are dropped, fully null rows are removed, and string columns are stripped of whitespace. Columns containing nested structures like geolocation dictionaries are serialized to JSON strings before deduplication to prevent comparison errors. A row index and load timestamp are appended to every record as pipeline metadata. Each load fully replaces the target table on every run rather than appending incrementally.

The dispatch DAG triggers a fourth DAG on completion: a spatial join DAG that reads the loaded dispatch records, filters to rows with valid latitude and longitude coordinates, and performs a point-in-polygon join against the MCPD police district shapefile using GeoPandas. Matched records are written to a separate table with the corresponding shapefile object ID attached, enabling Tableau to join directly to the shapefile by that ID. Records missing coordinates are retained in the output with a null district value rather than dropped. Once all that is done, data is prepped for automatic export to GitHub, Tableau, and any database connection. There is also the capability to load directly into a Google Sheet because I was considering that as a short-term storage option at some point.
